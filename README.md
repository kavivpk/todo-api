# To-Do REST API

A Java and Spring Boot REST API for creating, managing, searching, and filtering to-do tasks. The project demonstrates a layered backend design, request validation, consistent error responses, SQLite persistence, automated integration tests, and interactive OpenAPI documentation.

> **Portfolio demo:** This is a learning/demo application. Its SQLite database is local, and it does not include authentication or authorization.

## Problem statement

Simple task tracking is a useful way to practice backend fundamentals: accepting and validating HTTP requests, separating web and persistence responsibilities, storing records, and communicating errors with standard HTTP status codes. This API provides those operations through a compact REST service.

## Features

- Create, list, retrieve, update, and delete tasks.
- Assign task IDs automatically.
- Reject blank task titles and malformed request data.
- Return consistent JSON errors for invalid input and missing task IDs.
- Filter by completion state and search titles without case sensitivity.
- Persist tasks in a local SQLite database through Spring Data JPA and Hibernate.
- Expose interactive Swagger UI and an OpenAPI JSON document.
- Open Swagger UI automatically after successful startup on port 8080 when desktop/browser launching is available.
- Exercise the API with Maven integration tests and an importable Postman collection.

## Architecture

Requests follow this flow:

```text
HTTP client / Swagger UI
          |
          v
TaskController  ->  TaskService  ->  TaskRepository  ->  Hibernate/JPA  ->  SQLite
          |
          +---- ApiExceptionHandler (@RestControllerAdvice)
```

- **Controller** — maps HTTP routes to service calls, validates request bodies, and sets response statuses.
- **Service** — contains task operations and handles task-not-found lookup behavior.
- **Repository** — extends `JpaRepository<Task, Long>` and defines Spring Data query methods for filters/search.
- **Model** — `Task` is the JPA entity stored in SQLite.
- **Exception advice** — translates validation, malformed requests, and missing IDs into JSON error responses.

## API reference

Base URL: `http://localhost:8080`

| Method | Endpoint | Purpose | Success |
|---|---|---|---|
| GET | `/api/hello` | Check that the API is running | `200 OK` |
| GET | `/api/tasks` | List tasks; optional filters below | `200 OK` |
| GET | `/api/tasks/{id}` | Retrieve a task | `200 OK`; `404 Not Found` if absent |
| POST | `/api/tasks` | Create a task; ID is generated by the server | `201 Created` |
| PUT | `/api/tasks/{id}` | Replace task title, description, and completion state | `200 OK`; `404 Not Found` if absent |
| DELETE | `/api/tasks/{id}` | Delete a task | `204 No Content`; `404 Not Found` if absent |

### List, filter, and search

`completed` and `search` are optional and can be combined. Search matches a keyword in the task title, ignoring case. No matches return `200 OK` with `[]`.

```text
GET /api/tasks
GET /api/tasks?completed=true
GET /api/tasks?completed=false
GET /api/tasks?search=SQL
GET /api/tasks?completed=true&search=SQL
```

### Create a task

```http
POST /api/tasks
Content-Type: application/json
```

Request:

```json
{
  "title": "Learn SQL",
  "description": "Practice SQL queries",
  "completed": false
}
```

Example `201 Created` response (the ID is generated and will vary):

```json
{
  "id": 1,
  "title": "Learn SQL",
  "description": "Practice SQL queries",
  "completed": false
}
```

### Get a task

```http
GET /api/tasks/1
```

Example `200 OK` body:

```json
{
  "id": 1,
  "title": "Learn SQL",
  "description": "Practice SQL queries",
  "completed": false
}
```

### Update a task

```http
PUT /api/tasks/1
Content-Type: application/json
```

Request:

```json
{
  "title": "Learn SQL",
  "description": "Practice SQL queries",
  "completed": true
}
```

Returns the updated task with `200 OK`.

### Delete a task

```http
DELETE /api/tasks/1
```

Successful deletion returns `204 No Content` with an empty body.

### Error responses

Blank titles, malformed JSON, and invalid query parameter values return `400 Bad Request`. A task ID that does not exist returns `404 Not Found`.

Example:

```json
{
  "status": 400,
  "error": "Bad Request",
  "message": "title: Title must not be blank"
}
```

## Requirements

- Windows 10/11 (commands below use PowerShell).
- JDK 21 installed and available on `PATH`.
- Internet access the first time Maven needs to download dependencies.
- Port `8080` available, or choose another port at launch.
- VS Code with the Extension Pack for Java is recommended for IDE support.

The Maven Wrapper (`mvnw.cmd`) is included, so a separate Maven installation is not required.

## Run from Windows PowerShell

Open PowerShell and change to the Maven project root:

```powershell
Set-Location 'E:\frontend\Todo-api\todo-api'
java -version
.\mvnw.cmd clean test
.\mvnw.cmd spring-boot:run
```

The API uses `jdbc:sqlite:todo.db`. This is a **relative path**, so launch from the project directory above to use the project-root database file. The application creates/updates its schema using Hibernate. Keep the database local; do not put real or personal task records in a public portfolio repository.

If port 8080 is occupied, identify the listener before stopping anything:

```powershell
Get-NetTCPConnection -LocalPort 8080 -State Listen |
    Select-Object LocalAddress, LocalPort, OwningProcess
```

You can use a different port without stopping the other process:

```powershell
.\mvnw.cmd spring-boot:run "-Dspring-boot.run.arguments=--server.port=8081"
```

The Swagger browser launcher intentionally opens its fixed URL only when the server port is 8080. On another port, open Swagger manually at `http://localhost:8081/swagger-ui/index.html`.

## Run from VS Code

1. In VS Code, choose **File → Open Folder...** and open `E:\frontend\Todo-api\todo-api` (the folder containing `pom.xml`).
2. Allow the Java and Maven extensions to import the project.
3. Open `src/main/java/com/example/todo_api/TodoApiApplication.java`.
4. Select **Run** above the `main` method, or run this in the integrated PowerShell terminal:

   ```powershell
   .\mvnw.cmd spring-boot:run
   ```

5. Wait for the `Started TodoApiApplication` log message. With port 8080 available, the app attempts to open Swagger UI automatically. If that is unavailable, use the manual URL below.

## Postman collection

The collection is at [`postman/To-Do-API.postman_collection.json`](postman/To-Do-API.postman_collection.json).

1. Start the API.
2. In Postman, choose **Import → File** and select the collection JSON file.
3. Run **To-Do REST API - Complete Test Collection** with `baseUrl` set to `http://localhost:8080`.
4. The collection covers valid CRUD operations, completion filters, case-insensitive search, empty results, blank-title and malformed-JSON errors, missing IDs, and cleanup.

Collection cleanup targets only task IDs created by a successful create request in that collection run. The API has no authentication; run the collection only against your local development server.

## Data, secrets, and GitHub portfolio safety

- The local SQLite database is ignored and should not be committed. Use synthetic demo data only.
- Local environment files, private keys/certificates, IDE metadata, logs, and build output are ignored.
- No credentials are required by the current local configuration.
- `todo.db` was already tracked before this portfolio preparation. It is now removed from the Git index while the local file is preserved, so it will be absent from the next committed snapshot. This does **not** remove the database from earlier commits; the current `origin/main` history contains it. Do not publish/push the next commit to a public repository if that database contains personal or sensitive records.
- `.gitignore` only prevents future untracked files from being added; it does not erase files from existing commits. If sensitive data was committed previously, rotate any exposed credentials and follow repository-host guidance for handling history.
- Do not force-push or rewrite the existing project history as part of this setup.
